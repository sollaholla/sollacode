# Web Push

`packages/contracts/src/webPush.ts` defines browser subscriptions, per-installation preferences, and four authenticated RPCs: status, subscribe, unsubscribe, and test. The shared client runtime exposes the RPC commands; the web client presents them under Settings → Agents. Native mobile and Electron continue using their existing notification paths. This implementation does not add native push tokens or change provider adapters.

`WebPushReactor` bridges provider-neutral orchestration activities (`approval.*` and `user-input.*`, including tool action approval prompts) and `VmAgentWorkspace.subscribeAttention`. It recovers recent pending requests and unread agent alerts from projections at startup. Providers that emit those activities are supported without adapter-specific delivery logic.

`WebPush` persists endpoint subscriptions tied to the authenticated session and a deduplicated delivery outbox in migration 78. Registration requires both agent and thread read access. Each endpoint/event key is unique. Subscription age excludes pre-opt-in history; categories and private-by-default payloads are applied before enqueueing. Preference changes settle pending deliveries, and unsubscribe removes them through the foreign key. Request resolutions cancel pending request deliveries.

A scoped drainable worker performs bounded delivery using `web-push`, with a 30-second retry wake, exponential backoff, at most eight attempts, a one-hour vendor TTL, and 24-hour outbox retention. HTTP 404/410 removes expired endpoints; temporary failures retry. Active session, expiry, revocation, and scopes are checked before each batch. Endpoint URLs are limited to supported HTTPS vendor push services, and provider response bodies/endpoints are excluded from logs and client errors. A stable VAPID key pair is created lazily through `ServerSecretStore`; the private key is never sent to a client. The test action reports acceptance rather than claiming on-device delivery.

The outbox is best effort and can deliver twice if the process stops after the vendor accepts a push but before the receipt is persisted. Stable notification tags let the browser replace an existing notification for the same event. Already-accepted notifications cannot be recalled by resolving a request or disabling push.

The root-scoped `web-push-worker.js` displays push messages and constrains notification destinations to the current origin. A tap focuses/navigates an existing window or opens one. It has **no fetch handler or app-shell cache**, so adding it does not pin clients to old bundles. The manifest enables Home Screen standalone mode. Permission is requested synchronously from a user tap; no permission is requested on page load. Browser subscriptions are replaced if the host's public key changes.

Push is per origin and primary host, not aggregated across all saved environments. Vendor delivery requires outbound internet; a private HTTPS Tailscale origin is sufficient and does not need inbound public exposure. Actual device delivery and OS permission behavior require on-device verification; transport, worker, DOM, and integration tests do not establish that acceptance layer.
