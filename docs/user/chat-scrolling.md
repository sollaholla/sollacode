# Reading while a response generates

The transcript follows new output while you are at the bottom. Scroll toward older messages to pause following. New text, images, and completed work then keep your reading position.

Expanding or collapsing a tool, a turn, a long message, or a file list keeps the control you used in place as the content is measured. If you were following new output and the control remains at the bottom, following continues without showing **Scroll to end**. If the expansion leaves newer content below your view, following pauses so you can read the expanded content. Changing table expansion or code wrapping behaves the same way.

Use **Scroll to end**, send a message, or scroll toward the bottom to follow new output again. Within the last 48 pixels, downward scrolling rejoins live output and closes the remaining gap. Scrolling upward, even just a few pixels, keeps your reading position.

This behavior applies to the web client and the desktop apps that use it, including a web client connected to a remote environment.

On touch screens, height corrections keep the visible rows and scroll range in the same position throughout a flick. Once scrolling settles, the measured layout and scroll offset update together. On browsers that report when native scrolling ends, that event keeps the gesture open through momentum and bounce. Reaching the bottom clears **Scroll to end**, even when the final finger movement recoils slightly without moving the view away from the bottom. Returning to a thread restores its saved position once; ongoing scroll updates do not restart that restore. Touching or scrolling the transcript also releases any completed initial-position correction, so it cannot pull you back later.

The new-thread heading, notices, and composer share one layout below the toolbar and usage row.
On short screens the form scrolls instead of overlapping those controls. Focusing the phone's
message editor docks the composer above the keyboard; tapping a status chip does not dock it.

Connection and waiting-message indicators are separate icon buttons with matching styling, aligned
on the right beside the terminal and side-chat indicators. Tap either icon for its details and
actions; message counts and status are also available to screen readers and in hover text.
The connection icon disappears when the connection recovers.

Generic provider “Thinking” and “Generating” receipts without content do not create empty reply boxes or work-log entries. The Working indicator shows active progress; actual reasoning, tool results, and errors remain in the conversation. This also applies to saved conversations and the native mobile feed.

OpenCode tool rows show the shell command or affected file paths, with the output available when
expanded. Tool errors and nonzero command exit codes appear as failures. This applies to new and
saved activity in web, desktop, and native mobile, including remote connections.

Side drawers slide in and out from their screen edge. Dialogs and controls use short transitions, with no continuous decorative animation. Drawer and dialog transitions are disabled when your device requests reduced motion.
