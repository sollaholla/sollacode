# Reading while a response generates

The transcript follows new output while you are at the bottom. Scroll toward older messages to pause following. New text, images, and completed work then keep your reading position.

Expanding or collapsing a tool, a turn, a long message, or a file list also pauses following. The control you used stays in place as the content is measured. Changing table expansion or code wrapping behaves the same way.

Use **Scroll to end**, send a message, or scroll all the way to the bottom to follow new output again. Scrolling close to the bottom does not resume following early.

This behavior applies to the web client and the desktop apps that use it, including a web client connected to a remote environment.

The new-thread heading, notices, and composer share one layout below the toolbar and usage row.
On short screens the form scrolls instead of overlapping those controls. Focusing the phone's
message editor docks the composer above the keyboard; tapping a status chip does not dock it.

Connection notices start as a compact **Reconnecting…** or **Disconnected** chip. Tap or click it
to expand the connection details, saved-message guidance, and reconnect/settings controls. Tap
again to collapse it. The notice disappears when the connection recovers.

Generic provider “Thinking” and “Generating” receipts without content do not create empty reply boxes or work-log entries. The Working indicator shows active progress; actual reasoning, tool results, and errors remain in the conversation. This also applies to saved conversations and the native mobile feed.

OpenCode tool rows show the shell command or affected file paths, with the output available when
expanded. Tool errors and nonzero command exit codes appear as failures. This applies to new and
saved activity in web, desktop, and native mobile, including remote connections.
